# Microsoft 365 Copilot Prompt Library — Investment Firm Edition

## Purpose & How To Use This Deliverable

This workbook provides 110 ready-to-use Microsoft 365 Copilot prompts tailored to an investment firm (hedge fund / asset manager / private equity context). It is structured so each row can be copy-pasted directly into an Excel sheet using four columns: **Department | Use Case | Prompt | Example**.

**Prompt Framework Used (Microsoft’s “GCSE” Pattern):** Every prompt is built around four elements Microsoft recommends:

- **Goal** — what you want Copilot to do  (verb-led: summarize, draft, analyze, build).
- **Context** — audience, purpose, constraints  (e.g., “for the IC”, “for an LP update”).
- **Source** — the specific Outlook thread, SharePoint folder, Excel file, or PowerPoint deck Copilot should ground in. Source-grounding is the single biggest driver of accuracy and the strongest defense against hallucination. 
- **Expectations** — output format, length, and tone (table, 3 bullets, 1-page memo, formal tone).

**Important environment note:** The firm’s Copilot has access to **Outlook, PowerPoint, SharePoint, and Excel — but NOT Teams meeting transcripts/recordings.** Prompts therefore reference emails, files, and folders rather than meeting recaps. Where a “meeting prep” prompt appears, it draws on emails and attached materials, not transcripts.

**Tips before you start:**

1. Always tell Copilot *where* to look (file name, SharePoint site, sender, date range). Vague prompts produce vague answers.
1. One goal per prompt  — chain follow-ups instead of stacking goals.
1. Specify output format (“table with 4 columns”, “5 bullet points”, “1-page memo”).
1. Iterate. Copilot expects a conversation;  refine, don’t restart.
1. Always verify numbers, citations, and regulatory references before external use.

## Implementation Recommendations for the Firm

1. **Pilot with 2-3 departments first** (recommended: Investment/Research, IR, and Compliance) where the volume of repeated synthesis work delivers the fastest ROI.
1. **Standardize file paths and SharePoint structure** before broad rollout — Copilot’s quality drops sharply when sources are scattered across personal OneDrives. The prompts in this library assume well-organized, permissioned SharePoint libraries.
1. **Establish a “Prompt Library” SharePoint site** where users can save, tag, and share refined prompts that work well. Treat prompts as institutional knowledge.
1. **Always human-review Copilot output before external use**, especially anything touching performance numbers, regulatory citations, LP communications, or legal language. Copilot can confidently hallucinate;  the four-part GCSE framework (Goal, Context, Source, Expectations) reduces but does not eliminate this risk.
1. **Acknowledge the no-Teams-meetings constraint** in user training — coach staff to capture decisions in Outlook recaps or SharePoint notes so Copilot has grounded content to draw on for follow-ups.
1. **Compliance and Legal should pre-approve a list of “do-not-use” data sources** (e.g., MNPI folders, deal-team-only sites) and configure Microsoft Purview sensitivity labels accordingly before broad enablement.
1. **Measure adoption with concrete KPIs**: time saved on month-end close, DDQ turnaround, IC memo first-draft cycle time, and LP-letter drafting time are all good early metrics.

This library should be treated as a starting baseline. Encourage employees to fork and refine prompts for their specific workflows — the firms that get the most value from Copilot are those that build a culture of prompt iteration rather than treating prompts as fixed scripts.
